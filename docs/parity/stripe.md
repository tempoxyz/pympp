# Stripe parity (`mpp.stripe`)

Owner: stripe. Reference: mppx `src/stripe/**`, spec `specs/methods/stripe/draft-stripe-charge-00.md`.
Tests: `tests/stripe/` (147 tests).

| mppx feature | Status | Notes |
|---|---|---|
| `Methods.charge` schema (amount via `parseUnits`, `methodDetails` {networkId, paymentMethodTypes, metadata}, `externalId`, `recipient`, `description`; payload `{spt, externalId?}`) | Implemented | `mpp.stripe.charge` / `ChargeRequest` / `ChargePayload`. Inputs accept snake_case or camelCase keys; wire keys are camelCase. `decimals` is a strict int (zod rejects strings too). |
| `parseUnits` (round half away from zero, viem-compatible) | Implemented | `mpp.stripe._internal.units.parse_units`; hypothesis test against a Decimal reference replaces the viem fast-check comparison. |
| `paymentIntentOptions` (customer, hooks.inputs.tax.calculation, metadata, receipt_email; or a lazy resolver), stripped from challenges | Implemented (request-scoped) | `payment_intent_options=` route option only. Unknown keys ignored like zod. Resolver gets `ResolveContext(challenge, credential, envelope, request)`. mppx's `stripe.charge()` type accepts the key but its runtime never forwards it as a default. Every changelog entry (f494ffd, 5cbc5e4, c74d2ce) and every test (`Charge.test-d.ts`, `Methods.test-d.ts`) describe or use the options as request-scoped. So `stripe.charge()` has no such parameter here: passing it raises `TypeError` rather than being silently dropped. |
| Client `stripe.charge({createToken, client, externalId, paymentMethod})`, context `paymentMethod`, `expiresAt` (challenge expiry or now+1h), request-bound externalId precedence, reserved `metadata.externalId` | Implemented | `mpp.stripe.client.charge(create_token=..., client=..., external_id=..., payment_method=...)`; `create_token(TokenParams)`. `stripe(...)` group returns `[charge]`. |
| Server `stripe.charge({client \| secretKey, ...defaults, canOffer, onPaymentSuccess})` | Implemented | `mpp.stripe.server.charge`. `secret_key` uses `StripeHttpClient` (httpx, same endpoint/form params/headers/`Stripe-Version`). Passing both/neither raises `TypeError` (mppx: type-level only). |
| Stripe minimum charge amounts per currency + composed `canOffer` | Implemented | `MINIMUM_CHARGE_AMOUNTS`. |
| PaymentIntent creation: `automatic_payment_methods`, `confirm`, `shared_payment_granted_token`, analytics metadata merge order, idempotency key `mpp_{challengeId}_{spt}`, `Idempotent-Replayed` → "already processed", `requires_action` → `PaymentActionRequiredError`, other non-succeeded → internal error | Implemented | Spec example key is `{id}_{spt}`; mppx's `mpp_` prefix wins. |
| externalId binding (credential must echo request-bound id; receipt attributes server value only) | Implemented | Conformance vector `stripe-external-id-binding.json` passes (`test_stripe_conformance.py`). |
| `StripeClient` duck typing (Stripe Node SDK shape) | Intentionally different | Python protocol `StripeClient.create_payment_intent(params, *, api_version, idempotency_key, stripe_account) -> PaymentIntent(id, status, replayed)`; `StripeRawClient.raw_request(...)` for machine payments. `StripeHttpClient` implements both. Users of another Stripe SDK write a tiny adapter. |
| `stripe.create()` machine payments: `spt.charge`, `tempo.charge`, `findOrCreateDepositAddress`, `defaultMethods({exclude}).additional({...})` | Implemented (renamed) | `create(...) -> MachinePayments` with `spt_charge`, `tempo_charge`, `find_or_create_deposit_address`, `default_methods(exclude=, rails=)` (static addresses) and `await load_default_methods(...)` (async resolver; failed networks excluded with a warning). mppx's sync-or-thenable return has no Python analog. |
| Caller options override rail defaults (`tempo_charge`: `can_offer`, `on_payment_success`, `testnet`, `fee_payer`) | Implemented | Same as mppx spreading `...rest` after the defaults. |
| Store guards (atomic store required; per-charge store and `storeKeyPrefix` rejected), `rawRequest` required, testnet currency/chain | Implemented | |
| Crypto rails 1-cent minimum (10_000 raw units) composed before user `canOffer` (also for custom rails) | Implemented | |
| `withPaymentIntentInput` (options accepted on any rail, stripped from challenge and rail hooks, resolved after `validate` and before `broadcast`/`verify`, kept in `request_input` for recording) | Implemented | `with_payment_intent_input(ServerMethod)`; wraps the rail's request model. |
| Record payment (`transaction_verification`, cents conversion, retry once without optional fields on definitive invalid-request errors with `_fallback` idempotency key, never raises) | Implemented | Logs via `logging.getLogger("mpp.stripe")` instead of `console`. Definitive errors: `type in {"invalid_request_error","StripeInvalidRequestError"}` or stripe-python `InvalidRequestError`. |
| Deposit addresses (list `?network=..&limit=1`, else create; cached per client) | Implemented | Cache keyed by `id(client)` with weakref cleanup (clients need not be hashable). |
| Analytics metadata (`machine_payment`, `mpp_sdk`, `mpp_intent`, `mpp_challenge_id`, 500-char limit) | Implemented | `mpp_sdk` is `pympp/<version>` (mppx: `mppx/<version>`). |
| `mppx/stripe/server/spt` entry point (SPT without chain rails) | Not needed | `mpp.stripe.server` imports Tempo lazily, so importing it never loads rail dependencies (tested). `server.spt` is an alias of `server.charge`. |
| Deprecated `stripe.charge` alias of `stripe.spt` | Implemented as the primary name | `charge` and `spt` are the same function. |
| Live Stripe integration test (`Charge.integration.test.ts`) | Not ported | Requires a real Stripe secret key / network. |
