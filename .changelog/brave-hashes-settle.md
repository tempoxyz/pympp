Mapped server verification errors to payment errors. `VerificationError` now subclasses `VerificationFailedError`, so invalid credentials return a 402 with a fresh challenge instead of escaping as an unhandled exception. Added `CredentialReplayedError`, a `VerificationError` subclass with status 403 and the `verification-failed` problem type, for Tempo transaction hashes that were already used or are being settled by a concurrent request, and for settled transfers whose memo is bound to another challenge. The `pay` decorator answers it with a final 403 and no `WWW-Authenticate` challenge, so auto-paying clients do not pay again for a payment that already settled. Added `InternalPaymentError` (status 500) for RPC, fee payer and configuration failures, missing receipts, and any non-cancellation failure after a Tempo transaction is broadcast. Its message is generic and the original exception is kept only as `__cause__`. Servers and the MCP transport re-raise it without a retry challenge, so clients are not asked to pay again for a payment that may have landed.
