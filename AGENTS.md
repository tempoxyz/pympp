# pympp

The Python SDK for MPP, published to PyPI as `pympp` and imported as `mpp`. It covers both sides of a paid HTTP exchange: an httpx client that answers `402` responses and a server (`Mpp`, ASGI and decorators) that issues Challenges and verifies Credentials, with Tempo, Stripe and EVM payment methods, MCP, x402 interop and Redis and SQLite stores. User-facing usage and upgrade notes are in [README.md](./README.md).

## Commands

```bash
uv sync --all-extras --dev                 # install (make install)
uv run ruff check .                        # lint (make lint)
uv run ruff format --check .               # format check (make format-check)
uv run pyright                             # strict type check (CI runs pyright-action on the venv)
uv run python scripts/public_api.py --check   # public API snapshot is current (make api-check)
uv run pytest -v --cov=mpp --cov-report=term-missing --cov-fail-under=90   # tests, Python 3.11 to 3.14 in CI
uv build && uv run twine check --strict dist/*   # package
```

`make check` runs lint, format check, API check and tests; `make fix` applies ruff fixes and formatting. Run one test with `uv run pytest tests/test_challenge_id.py::test_name -v`.

Without services, `integration`, `redis` and `x402_localnet` tests skip. CI's integration job runs the whole suite against Docker: `docker compose up -d --wait` (Tempo localnet, Anvil, Redis), `npm ci --ignore-scripts --prefix tests/fixtures/x402/mppx-server` and `npm ci --ignore-scripts --prefix tests/interop/mppx_session` for the mppx interop fixtures, then `make coverage` (sets `TEMPO_NETWORK=localnet`, `REDIS_URL`, `X402_ANVIL_RPC_URL`), which fails if branch coverage drops below `.coverage-baseline`; `make diff-cover` then needs 90% on changed lines. `make test-integration` runs only the localnet tests (`make node` starts the localnet), and `TEMPO_NETWORK=moderato` targets the public testnet. Stress tests need `MPP_STRESS=1`. Mutation testing (`make mutation`) and fuzzing (`make fuzz`) run on schedules, not on pull requests.

## Layout

- `src/mpp/__init__.py`: Challenge, Credential and Receipt types and Challenge ID binding (`generate_challenge_id`, constant-time comparison); `_parsing.py` parses and formats the headers, `_canonical.py` does JCS, `_body_digest.py` the body digest.
- `src/mpp/client/`: the httpx client and transport that pay `402` responses.
- `src/mpp/server/`: `Mpp`, Challenge issuance and verification (`verify.py`), method composition, ASGI and decorator integration.
- `src/mpp/methods/{tempo,stripe,evm}/`: payment methods; Tempo sessions are in `methods/tempo/session/`.
- `src/mpp/extensions/mcp/`: the MCP transport. `src/mpp/x402/`: x402 client, server and facilitators.
- `src/mpp/store.py`, `src/mpp/stores/`: the store interface, `MemoryStore`, and the Redis and SQLite stores.
- `api/public-api.txt`: the public API snapshot, generated by `scripts/public_api.py`.
- `tests/`: pytest suite; `tests/network.py` picks the Tempo network, `tests/fixtures/` and `tests/interop/` hold mppx fixtures.
- `scripts/`: public API dump, coverage ratchet and mutation report. `fuzz/`: atheris targets. `examples/`: runnable examples.
- `.changelog/`: pending changelog fragments and `config.toml`.

## Conventions

- Python 3.11+, ruff (line length 100) and strict pyright on `src/`. Do not commit a lockfile: CI resolves dependencies fresh with `UV_EXCLUDE_NEWER=7 days`.
- Optional dependencies stay behind extras (`tempo`, `stripe`, `evm`, `server`, `mcp`, `x402`, `redis`, `sqlite`, `cdp`). Packages that re-export extra-only names do it lazily through `_lazy_exports.py` with a matching `__init__.pyi`, so a base install imports and the error names the `pympp[extra]` to install. Client imports must never load `mpp.server` (`tests/test_import_isolation.py`); CI smoke-tests the built wheel per extra.
- After an intended public API change, run `make api` (Python 3.12, all extras) and commit `api/public-api.txt`; CI fails on drift.
- Match mppx's names, defaults and errors, as the shared section below says.
- Do not write a `.changelog/` fragment by hand. When a pull request is opened, the Changelog workflow (`.github/workflows/changelog.yml`) runs `changelogs add --ai` and commits the fragment to the branch, unless the change only touches `.changelog/`, `.github/`, `README.md` or `AGENTS.md`; a hand-written one duplicates its entry. It runs only on `opened`, so edit its fragment if later commits change the scope. Fragments look like:

  ```markdown
  ---
  pympp: patch
  ---

  Fixed ... (past tense, user-facing).
  ```

- Commits and pull request titles use Conventional Commits (`feat: ...`, `fix: ...`); the release workflow reads them.
- Protocol changes run the mpp-tools conformance suite with the `python` adapter (`conformance.yml`).

## Releases

Releases use [changelogs](https://github.com/tempoxyz/changelogs) (`publish.yml`). A push to main opens or updates a version pull request that bumps `pyproject.toml` and writes `CHANGELOG.md` from the fragments; merging it publishes to PyPI through trusted publishing. A Monday 15:17 UTC run sets that pull request to auto-merge. Never edit `CHANGELOG.md` or the version by hand.

### This file

- Keep it to `# <repository>` and a short paragraph, then `## Commands`, `## Layout`, `## Conventions`, then only the sections this repository needs, then this section.
- Write rules an agent can act on: commands, paths, constraints. Leave out background, history and anything the code, specs or README already say.
- When you learn a convention the hard way, add it to the section it belongs to in the same pull request.

### Code

- Make the smallest change that does the job and follow the surrounding code. Start concrete; extract an abstraction only once several real uses share it.
- Keep the public API narrow. Add rather than remove or rename, and mark what you replace as deprecated before deleting it.
- Document every exported item (JSDoc, rustdoc, docstrings, Go doc comments). Comments say why, not what.
- Match mppx, the reference SDK: its names (Challenge, Credential, Receipt, Method), defaults, errors and behavior, unless the language forces otherwise; say why when it does.
- The IETF drafts in tempoxyz/mpp-specs (paymentauth.org) are the source of truth for the protocol, and mppx settles what they leave open. Link them instead of restating them.
- Add no dependency without a reason the pull request states. Prefer the standard library and what the repository already uses.
- Never log or commit keys, credentials, signatures, authorization headers or raw upstream errors.
- Tempo chain IDs: mainnet `4217`, Moderato testnet `42431`. Never `98865`.

### Tooling

Use each language's standard toolchain, run through the commands in `## Commands`, and keep it clean with warnings as errors:

- TypeScript: pnpm, strict `tsc`, ESM with `.js` relative imports, the repository's configured formatter and linter, Vitest.
- Python: uv, ruff (format and lint), a strict type checker (pyright or ty), pytest or unittest.
- Rust: cargo, `cargo fmt`, `cargo clippy -D warnings`, `cargo test`.
- Go: `gofmt`, `go vet`, golangci-lint, `go test -race`.
- Swift: SwiftPM, `swift test -Xswiftc -warnings-as-errors`.
- Run the checks that cover your change before opening a pull request, and add tests for behavior that matters, next to the existing ones.
- Pin GitHub Actions by full commit SHA. Workflows start with `tempoxyz/gh-actions/actions/secure-runner` and get write tokens from GitHub STS policies in `.github/sts/`, never stored secrets.

### Changes

- Commits and pull request titles use Conventional Commits: `feat:`, `fix:`, `docs:`, `refactor:`, `test:`, `chore:`, optionally scoped.
- Never edit `CHANGELOG.md` by hand. Record a release note the way `## Conventions` says (changeset, `.changelog/` fragment, or none when a workflow writes it), in the past tense.
- Before 1.0, bump `patch` for everything except a breaking public API change, which is `minor`.
- Don't edit README files unless asked.
- Never force-push.

### Docs and prose

- Active voice, present tense, second person. Sentence-case headings. No filler (just, simply, easily) and no Latin abbreviations.
- Capitalize Challenge, Credential and Receipt as MPP concepts. Say stablecoins, not crypto, and USDC.e for bridged USDC on Tempo. Write `mppx` in lowercase.
